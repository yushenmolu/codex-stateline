# Codex Stateline 功能与 UI 审查报告

**日期**：2026-10-26\
**结论**：确认 **10 项问题：1 项高、5 项中、4 项低**。其中 4 项功能问题、6 项 UI / 可用性问题。\
**原则**：只审查，不修复；不把个人审美、正常防御性截断或短暂保留旧数据直接当成 bug。

## 一、优先结论

1. **首先修复 Web 模型目录绑定。** 页面保留的是示例模型，真实目录未接入；用户无法选择当前真实模型，部分看似可选的配置会被服务端拒绝。这是直接影响主流程的高严重度问题。
2. **随后处理运行恢复与轮询可靠性。** 响应结果未知时不能换新幂等键盲目重试；状态 GET 必须有超时和恢复机制。
3. **再修复辨识与编辑连续性。** 同名任务不可区分、代理详情只依赖 tooltip、评分刷新丢失焦点，都影响日常操作。
4. **最后收束状态表达与细节。** 区分服务连接和任务级数据缺失、修正按钮对齐、缩小 live region，并明确浅色主题支持范围。

## 三、功能问题

### F-01｜高｜Web 基准配置与实时模型目录脱节

**复现**
1. 打开 Web 面板并展开“鹈鹕基准”。
2. 只读获取同源 `GET /api/benchmark`，比较 `defaults.availableModels` / `availableEfforts` 与下拉选项。
3. 比较静态示例模型与服务端当前 allowlist；无需真实运行。

**实际**
- 审计时服务端返回 8 个模型项，其中 `configured` 外的 7 个真实模型均未出现在 Web 下拉中；页面仍为 `configured + 3 个 example-provider 静态项`。
- 3 个静态示例对当前目录做纯 `isAllowedModel` 校验均为 false；提交会走 `schema_invalid` 路径。
- 服务端目录中的 `persistent`、`none` 推理强度也未出现在页面。
- “沿用配置”默认路径不受此项影响；本次没有发送真实运行 POST。

**预期**：Web 使用与服务端校验相同的目录，保留合法草稿，目录不可用时明确提示，不能以示例项充当真实配置。

**定位**
- `src/public/index.html:14`：硬编码模型与推理强度。
- `src/public/app.js:328-340`、`353-364`：渲染和提交未绑定 `availableModels` / `availableEfforts`。
- `src/server.js:89-91`、`128-144`、`282-294`：目录下发和提交校验。
- `src/benchmark/service.js:140-144`：服务层二次校验。

**修复方向**：根据快照生成选项，独立维护目录版本与合法草稿；目录失败时禁用明确选择。增加 DOM 初始化、目录变化和非法静态项测试。

### F-02｜中｜提交结果未知时换新 requestId 重试

**复现（安全 fixture）**
1. 初始化 idle 快照，使“启动基准”可用。
2. 模拟服务端可能已接受 `/api/benchmark/run`，但响应连接丢失。
3. 异常结算后再次点击启动，比较两次 payload。

**实际**
- 第一次失败后直接恢复旧 idle 按钮，没有“提交结果未知/先对账”的状态。
- 两次点击分别生成 `ui_...0001`、`ui_...0002`，第二次没有复用幂等键或先 GET 对账。
- 前次仍活动时新 ID 会得到 `run_active`；若前次已结束且活动记录清理，新 ID 可能产生第二次运行。不能夸大为每次重试必然重复扣费。

**预期**：无法确定服务端未接受时，先查询并对账；需要重试时沿用同一 requestId 和 payload，只有明确开始新运行才生成新 ID。

**定位**：`src/public/app.js:233-238`、`364`；`src/benchmark/service.js:152-157`、`167-176`、`188-192`。

**修复方向**：引入 `submissionUnknown`，保存请求键和 payload，未知时禁用启动并先拉取快照；覆盖响应丢失、活动中、完成后三类测试。

### F-03｜中｜一次状态 GET 挂起会永久阻断后续刷新

**复现（安全 fixture）**
1. 初次 `/api/benchmark` 返回 idle。
2. 下一次 GET 保持 pending。
3. 再触发三轮定时刷新，最后手动释放 pending 请求作为对照。

**实际**
- 后续三轮全部被 `state.polling` 跳过，请求总数保持为 2。
- 页面继续显示“未启动”，启动按钮仍可用，没有超时或过期提示。
- 手动释放后能够更新为“运行中”，证明阻塞点是未结算请求。若永久 pending，刷新页面成为唯一显式恢复方式。

**预期**：请求有明确期限；超时释放单 flight、标记旧状态过期并允许后续轮询恢复。

**定位**：`src/public/app.js:358-362`、`391`；对照遥测/capabilities 的 8 秒、5 秒超时在 `192-194`、`386-388`。

**修复方向**：使用 AbortController 和请求代次；`finally` 清理计时器与 flight，覆盖“挂起—超时—恢复”。

### F-04｜低｜固定任务的数据缺失被显示成整体连接不可用

**复现**
1. 固定一个非当前 follow 会话的任务。
2. 使任务元数据有效，但会话级 token/速度不可发布。
3. 对比 HTTP/任务详情与顶部连接指示。

**实际**
- HTTP 与 `task.id`、`stale`、`sampledAt` 等有效，顶部却显示“不可用”。
- 这是状态层级误导，不是跨任务计数错配；服务端对跨会话计数的清除是合理保护。

**预期**：服务连接、任务上下文、当前会话用量分开表达；不可归属的数据仍可保持未知。

**定位**：`src/public/app.js:38-58`、`222-227`；`src/server.js:241-267`。

**修复方向**：连接状态依据请求/服务可达性，任务数据状态在任务区域呈现；补充局部 unavailable 与真正断连的 DOM 测试。

## 四、UI / 可用性问题

### U-05｜中｜同名任务无法从选项可靠区分

**复现**：构造同名且 UUID 前 8 位相同的多个任务，打开任务下拉并比较可见标签。

**实际**
- 审计时 50 项样本有 8 组可见标签完全相同，组大小 `3/2/2/4/2/3/2/3`，每组完整 UUID 不同；数量随真实列表变化。
- 标题截到 44 字再加 8 位短 ID，重复组没有任何消歧信息。
- 选择值仍为完整 UUID，实测能选中对应项；这是可辨识性问题，不是已证实的数据绑定错误。

**预期**：重复项提供序号、时间/来源上下文或其他稳定消歧信息。

**定位**：`src/public/app.js:61`、`70`、`89-95`、`173-190`。

**修复方向**：在重复组追加稳定上下文/序号和补充可访问名称；覆盖同名、短 ID 冲突和超长标题。

### U-06｜中｜代理完整详情在触控和键盘下不可达

**复现**：320px 视口打开含代理信息的面板，用 Tab 和触屏尝试读取省略内容。

**实际**
- 行宽约 262.4px，样本 `scrollWidth` 为 265px、294px，内容被单行省略。
- 行是普通 `<p>`，`tabIndex=-1`；完整模型、推理强度、状态与关联回合只写入 `title`。
- 触控无可靠 hover，键盘也无法聚焦；容器最大高 72px，样本还存在约 1px 裁行风险。

**预期**：详情有键盘和触控可操作的展开入口，或允许字段换行；完整信息不能只靠 tooltip。

**定位**：`src/public/app.js:72-87`；`src/public/styles.css:460-479`。

**修复方向**：用语义化 button + 展开区域或可换行定义列表，支持 Enter/Space 和可见焦点。

### U-07｜中｜结果刷新使评分控件丢失焦点

**复现（合成只读快照）**
1. 评分 select 中把未保存草稿改为 5 并聚焦。
2. 下一轮快照包含非 progress 的变化，例如模型默认值改变。
3. 比较刷新前后的 DOM 节点和活动焦点。本审计只拦截 GET，没有保存评分。

**实际**
- 刷新前 `focused=true`、`value=5`；刷新后 `sameNode=false`、`activeElement=BODY`。
- 草稿值因 `state.drafts` 保留，但焦点和读屏上下文丢失。并非每次 progress 更新都触发，而是有效 render key 变化时整体重建。

**预期**：保留正在编辑的控件、焦点和上下文，只更新必要字段。

**定位**：`src/public/app.js:323-325`、`328-340`、`353-360`，尤其 `334` 的全量替换。

**修复方向**：按 run/case keyed 局部更新，必要时保存/恢复焦点；增加聚焦评分时收到快照的浏览器测试。

### U-08｜低｜推理强度与运行按钮错位

**复现**：展开“鹈鹕基准”，比较第二行两侧控件的垂直位置。

**实际**：桌面底边相差 20.47px；375px 复现约 20.5px。label 高约 50.5px，独立按钮 30px，从同一网格行顶开始。

**预期**：按钮与相邻 select 保持共同基线或底边。

**定位**：`src/public/index.html:14`；`src/public/styles.css:239-255`。

**修复方向**：按钮包装成同构 grid 项并保留标签空间，或按控件区域 `align-self:end`；检查窄屏及取消状态。

### U-09｜低｜高频遥测面板整体作为 live region

**复现**：用 MutationObserver 观察 `.panel[aria-live=polite]`，正常运行约 2.2 秒；读屏播报需另做人工验证。

**实际**：一次观察记录 28 次 `childList` 更新，任务计时、代理、指标和详情都位于同一 polite 区域。DOM 更新数不等于读屏必播次数，但存在反复干扰风险。

**预期**：仅简短连接、错误或关键状态主动播报；计时和普通遥测默认不进入 live region。

**定位**：`src/public/index.html:6`；`src/public/app.js:192-230`、`391`。

**修复方向**：移除面板级 live，仅给精简 status/error 节点设置 live；文本实际变化才更新，并用 NVDA/JAWS 人工验收。

### U-10｜低｜浅色主题未实际接入

**复现**：在 `prefers-color-scheme: light` 下打开页面，检查根元素与计算后的 `color-scheme`。

**实际**：`data-theme=null`、`color-scheme=dark`，没有切换入口。浅色 token 已存在，注释要求 JS 设置主题，但初始化没有实现。

**预期**：若支持浅色，应按偏好/用户选择设置并同步 `color-scheme`；若只支持深色，应明确范围并删除误导性注释。

**定位**：`src/public/tokens.css:100-147`；`src/public/index.html:3`；`src/public/app.js:391`。`docs/ui-redesign/codex-stateline-ui-redesign.md:675-678` 将其描述为“若要做”，所以此项按适配缺口列为低，不声称违反明确的主题功能契约。

**修复方向**：明确支持范围；实现时在首屏前设置主题、监听偏好或提供持久化切换，并复测对比度。
